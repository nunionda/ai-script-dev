# FRAME — 시나리오 개발 작업실

Final Draft처럼 표준 서식으로 시나리오를 쓰고, 장면 보드·작업본·AI 개발 파트너로 원고를 함께 발전시키는 웹 플랫폼입니다.
화면 구성은 `design/writers-room.html` 시안을 따릅니다.

## 실행

```bash
npm install
npm run dev          # API(8787) + 웹(5173) → http://localhost:5173
```

AI 개발 파트너를 쓰려면 Claude API 키를 넣고 실행합니다.

```bash
ANTHROPIC_API_KEY=sk-ant-... npm run dev
```

배포용: `npm run build && npm start` (API와 빌드된 웹을 `PORT`(기본 8787) 하나로 제공)

| 환경 변수 | 설명 |
|---|---|
| `ANTHROPIC_API_KEY` | AI 개발 파트너 활성화 |
| `FRAME_MODEL` | 사용할 Claude 모델 (기본 `claude-opus-5-5`) |
| `FRAME_DB` | SQLite 파일 경로 (기본 `data/frame.db`) |
| `PORT` | API 서버 포트 |

처음 실행하면 예시 작품 "마지막 상영"이 만들어집니다. `data/frame.db`를 지우면 다시 처음 상태가 됩니다.

## 기능

**집필 (Final Draft 방식 에디터)**
- 요소: 씬 헤딩 · 지문 · 인물 · 괄호 · 대사 · 전환 · 샷 · 일반
- `Enter`로 다음 요소 자동 전환(헤딩→지문, 인물→대사, 대사→지문), `Tab`/`Shift+Tab`로 요소 순환, `Ctrl+1~8` 직접 지정
- SmartType 자동 완성: 인물 이름, `내부./외부./INT./EXT.`, 장소, 시간대, 전환
- 페이지 나눔 실시간 표시(페이지당 55줄 기준, 한글은 2칸), 장면 번호 자동 매김
- 한국식(`S#1. 내부. 영사실 - 밤`) / 할리우드식(`1 INT. BOOTH - NIGHT`) 서식
- 찾기·바꾸기(`Ctrl+F`), 집중 모드(`Ctrl+Shift+F`), 실행 취소, 자동 저장 + 충돌 감지
- Fountain 텍스트 붙여넣기 시 요소 자동 인식

**스토리 구성** — 막별 인덱스 카드, 끌어서 순서·막 변경(원고에 반영), 장면 요약·의도, AI 요약, 열린 질문

**AI 개발 파트너** — 장면에 연결된 대화(스트리밍), 참조 범위(현재 장면 / 원고 전체), 답변을 팀 의견으로 공유,
장면 수정안 생성 → **수정안 검토** 화면에서 원문과 나란히 비교 · 채택 / 보류 / 거절 / 채택 취소 (채택 직전 원고는 작업본에 자동 저장)

**작품 바이블** — 판정서(R·D 번호, AI의 최우선 규칙), 하나의 행동, 하드 규칙(H 번호), 금지어, 참고 문서(시놉시스·트리트먼트·씬 로그·인물 설정서·장면 은행·취재 노트 전문),
태그 분류(모티프 셋업·변주·회수 / 횟수 한도 / 수위·재현), 장면 번호 고정(추가 장면 `S#41-1`, 삭제 장면 번호 유지).
**점검**은 코드가 직접 판정합니다: 그래서/그러나 연결어, 가치 전환, 횟수 한도, 모티프 장부, V.O., 금지어(〈극중극〉 예외), 【확정】 표현 변경

**AI 수정안 작성 과정** — 판정서·참고 문서를 프롬프트 맨 앞에 두고, 인용 근거 → 장면 카드 → 반클리셰 메모 → 집필 → 체크리스트 자기 검수(C1–C18) 순서로 씁니다.
코드 점검이나 자기 검수에 FAIL이 남으면 최대 2번 다시 씁니다. 【확정】 표현을 바꾼 수정안은 채택할 수 없습니다. 미결 쟁점(D-후보·고증·컨설턴트 검토)은 열린 질문으로 올릴 수 있습니다.

**역할 검수** — 수정안을 구조(STRUCT)·인물(CHAR)·대사(DIAL)·연출(DIR)·고증(RES)·윤리·수위(ETH)·전략(STRAT) 검수자가 따로 판정합니다.
검수자는 수정안을 쓴 AI와 대화를 공유하지 않는 새 호출로 같은 문서를 읽고, 판정·위험도·고칠 방향·컨설턴트 질문만 냅니다(원고는 바꾸지 않음). 작가가 눌러서 실행하며 1회 = AI 호출 1회.
수위·재현 태그나 수위 메모가 있는 장면은 ETH 검수 없이 채택하면 경고합니다.

**작가실 보조** — 작품 바이블의 씬 로그 인과 감사(STRUCT가 원고 전체를 장면별로 그래서/그러나·가치 전환·하나의 행동 판정),
컨설턴트 검토 목록과 장면별 확인 기록(보드), AI 대화 세션 정리(결정 후보 → 판정서, 미결 사항 → 열린 질문, 작가가 골라서 반영),
집필 중 【확정】 요소를 고치려 하면 확인 후 확정을 풉니다.

**영문 병행본** — 한국어 정본에서 할리우드 서식의 영문 병행본을 만들고 장면별로 번역합니다(STRAT 역할, 장면 1개 = AI 호출 1회).
정본의 판정서·참고 문서를 읽고 번역하며, 존댓말·호칭·사투리·말장난처럼 잃은 것은 번역 손실표로 남깁니다. 극중 원래 영어 대사는 `(in English)`로 표시합니다.
정본 장면이 번역 뒤에 바뀌면 "갱신 필요"로 표시하고, 장면 번호는 정본을 따릅니다(41-1 → 41A). 인물 이름 표기는 병행본마다 고정하며, 병행본에서 고친 내용은 정본에 반영하지 않습니다.

**팀 의견** — 장면별 의견, 해결 처리

**작업본** — 원고 스냅샷 저장, 현재 원고와 비교, 되돌리기

**리포트 · 설정** — 작품 정보, 함께 정한 방향(AI가 지키는 원칙), 인물별 대사·등장 통계와 설정, 장면 목록(쪽·분량 1/8), 장소

**가져오기 / 내보내기**
- 가져오기: Final Draft `.fdx`, Fountain `.fountain`, Word `.docx`, 한글 `.hwp`·`.hwpx`, PDF, 텍스트 `.txt`.
  Word·한글은 FRAME이 내보낸 문단 스타일(씬 헤딩·지문·인물·대사 …)을 그대로 읽고, 스타일이 없는 원고는 `S#12.`·`INT.` 헤딩, `이름 : 대사`, 이름 줄 아래 대사 같은 형태로 나눕니다.
  PDF는 들여쓰기 위치로 인물·대사를 구분합니다(글자가 없는 스캔본은 불가). 할리우드 표준 배치(Final Draft 등)와 한국 원고에서 흔한
  `3. 장소 (낮)` 번호 헤딩, 이름 칸·대사 칸으로 나뉜 줄, 쪽마다 반복되는 머리말·워터마크를 처리합니다. 첫 장면 앞의 기획의도·줄거리 등은 참고 문서로 함께 저장합니다.
  암호·배포용 한글 문서는 읽을 수 없습니다. 분류는 추정이므로 가져온 뒤 요소 종류를 확인해 주세요.
- 내보내기: Word `.docx`, 한글 `.hwpx`(요소별 문단 스타일 포함), Final Draft `.fdx`, Fountain `.fountain`, PDF(표지 포함 인쇄용 원고 → 인쇄 대화상자에서 PDF로 저장).

## 구조

```
shared/   도메인 로직 (요소 규칙, 페이지 계산, Fountain/FDX 변환, 비교, 자동 완성) + 테스트
server/   Express API, SQLite(node:sqlite) 저장소, Claude API 연동(ai.ts), 프롬프트(prompts.ts), 역할 검수(agents.ts)
src/      React 앱 — editor/(TipTap 기반 시나리오 에디터), views/, components/
design/   디자인 시안
```
